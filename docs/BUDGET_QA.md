# Aylık bütçe — cihaz kontrolü

14 Ekim 2026: tip/lint ve 14 suite / 280 test geçti; iOS/Android Hermes export başarılı. Gerçek cihaz kontrolleri henüz yapılmadı. Bütçe, seçili ay/para birimindeki kategori harcamalarına limit koyar; hesap bakiyesini değiştirmez. Limit başka aya otomatik taşınmaz.

1. Reload ve tam kapat/aç → Raporlar. SQLite v4 geçişi eski kayıtları korumalı. Geliştirme v3 seed'i dört örnek limit ekler: ilk demo ayının Yemek TRY `1.500,00`, Ulaşım TRY `500,00`, Genel USD `25,00`; önceki ay Yemek TRY `2.000,00`. Demo tarihi ilk yükleme ayına bağlıdır. 36 işlem kaydı ve mevcut düzenlemeler korunur.
2. Dokunulmamış sette demo ayı TRY: Yemek harcanan `946,25`, kalan `553,75`; Ulaşım harcanan `42,00`, kalan `458,00`. USD Genel `15,99` harcanan / `9,01` kalan. Önceki ay Yemek `2.370,00` harcanan / `370,00` aşım. Kayıtları daha önce değiştirdiysen beklentiyi kendi güncel giderlerine göre değerlendir.
3. Ana Sayfa → Kategoriler: Test bütçe adlı gider kategorisi oluştur. Raporlar → bu ay/TRY → Bütçe ekle: Test bütçe, `1000,00`, Kaydet; Raporlar düğmesiyle dön. Harcanan `0,00`, kalan `1.000,00` olmalı. Bu kategoriden TRY `250,00` gider ekle: harcanan `250,00`, kalan `750,00`. Aynı kategoride ikinci TRY hesabından gider de bu limite dahil olmalı.
4. Gideri `1200,00` yap: `200,00` Aşım yazmalı; çubuk en fazla tam dolu olmalı. Gideri silince harcanan sıfırlanıp kalan `1.000,00` olmalı. Gelir, başlangıç veya başka kategori/para birimi limitin harcamasına eklenmemeli.
5. Bütçe satırına dokun: form `1000,00` gruplamasız dolu gelmeli; ay/currency/kategori sabit. Limiti `1500,00` yap, Kaydet: tek limit güncellenmeli. Bu ay/TRY değişikliğinin önceki ay veya USD limitine etkisi olmamalı.
6. Bütçeyi kaldır → Vazgeç: limit aynı kalmalı. Onayla: yalnız limit kalkmalı; giderler/bakiyeler/rapor toplamları korunmalı. Tam yeniden açılışta kaldırılan demo limit seed ile geri dönmemeli. Aynı kategori/ay/currency için yeniden limit eklenebilir.
7. Boş/sıfır/negatif/fazla ondalık limit kaydedilmemeli. Taslakla geri çıkış uyarısı: devam etmek girdiyi korumalı, kaydetmeden çık limit oluşturmamalı. Aynı kategori/ay/currency için farklı ikinci limit girince güncel bütçeyi aç mesajı; mevcut satırdan düzenle. Çift Kaydet tek limit oluşturmalı.
8. Kategoriyi arşivle: geçmiş bütçe ve harcama korunmalı, mevcut limit düzeltilebilmeli. Yeni bütçe picker'ında arşivli veya gelir kategorisi seçilmemeli. Hesap arşivi geçmiş gideri bütçeden çıkarmaz.
9. Uygulamayı tamamen kapatıp aç, sonra Reload: limit/düzenleme/kaldırma korunmalı. Paket yüklüyken offline bütçe kaydetme/düzeltme/kaldırma. Expo Go ilk paket indirmesi Metro gerektirir; tamamen offline soğuk başlangıç native build ile ayrıca test edilir.
10. English/koyu tema: `1,000.50` girişi, `1,000.50` gösterimi, Remaining/Over budget. Büyük sistem yazısı/küçük ekran/yatay görünümde kategori ve Harcanan/Limit/Kalan metinleri okunmalı; klavye açıkken Kaydet kaydırarak erişilebilir olmalı. VoiceOver/TalkBack bütçe düzenleme eylemi ve tutarlarını okumalı.

Otomatik testler limit CRUD/retry/stale, dönem/currency ayrımı, arşiv geçmişi, migration rollback/retry, demo seed koruma ve dosyalı SQLite yeniden açılışı doğrular. UI testleri geçersiz tutar, hata taslağı, ön doldurma/kaldırma, route/ay, aşım ve EN-dark pending/refresh failure kapsamındadır. Native picker/klavye/gesture/görsel kabul mock UI testleriyle kanıtlanmaz.
